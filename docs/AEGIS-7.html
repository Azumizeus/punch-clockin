1. C'est quoi, PUNCH ?

PUNCH est une app mobile native (Expo / React Native) construite pour le hackathon Solana Mobile CLOCK IN. Elle fait partie d'un écosystème plus large appelé Nexus Seeker, qui a deux produits :

  • PUNCH (ce projet) — tu pointes une fois par jour depuis un vrai téléphone Seeker, une transaction Solana prouve ta présence, et tu accèdes à de petites missions payées.
  • PLI — un produit séparé (secret scellé, payant à lire, la chaîne ne voit jamais le contenu). PLI n'est pas touché dans ce projet.
Règle centrale : chaque paiement suit la même règle partout dans l'app — 92 % à la personne qui a fait le geste, 3 % à ceux qui gardent du SKR, 5 % à l'app. Affichée partout, jamais cachée.

2. Les deux bases de code

Deux projets distincts, ne jamais les confondre :

  1. punch-native (C:\Users\admin\Desktop\PUNCH\punch-native) — l'app mobile Expo/React Native. C'est celle-ci qui compte pour le hackathon.
  2. L'app de base web (Grok/xAI App Builder, dossier le plus récent : PUNCH-CLOCK-IN-19sept2026) — source de vérité du design : polices, couleurs, copy, structure d'écran.
Règle d'or répétée par l'utilisateur : « un clone, un jumeau, un miroir ». Toute divergence visuelle avec l'app de base est un bug, sauf fonctionnalités premium explicitement ajoutées (section 5).

3. Stack technique (punch-native)

  • Expo Router (routing par fichiers), groupe (tabs) avec header custom (TopBar).
  • Zustand (lib/punch/store.ts) avec persist (stockage MMKV).
  • @solana-mobile/mobile-wallet-adapter-protocol-web3js pour Seed Vault.
  • @solana/web3.js + @solana/spl-token pour les transactions et transferts réels.
  • Polices : Fraunces (titres), Figtree (corps), IBM Plex Mono (mono / reçus).
  • Thèmes : dark, light, gold — lib/punch/theme.ts.
  • Traductions FR/EN complètes dans lib/punch/copy.ts.

4. Économie réelle sur devnet

Règle explicite de l'utilisateur : « rien de fake, que du vrai fonctionnel premium ». Toute action qui touche à l'argent est une vraie transaction Solana devnet.

Infrastructure

  • Trésor devnet : FUiCbnDhEEJtz9Zcj66hGB54iGMGeyjRKD7CsTwpihJn. Clé dans lib/solana/treasurySecretDEVNET.ts, embarquée uniquement parce qu'on est en devnet.
  • Mints — USDC : vrai mint devnet Circle (4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU). USDT et SKR : mints SPL devnet créés pour la démo (le vrai SKR mainnet existe, mais pas sur devnet).
  • Helpers (lib/solana/wallet.ts) : sendUserToTreasuryTransfer, sendTreasuryToUserTransfer, sendTreasurySol.
Actions réelles dans store.ts

punchIn (mémo + frais d'entrée), leaveNetwork (mémo + frais de sortie), stake/unstake (transfert SPL + frais 1,5 %), swap (deux transferts, spread 0,35 %), postShift/cashShift/greetNearby (transferts réels).

Premier lien réel (connectReal)

Un wallet Seed Vault neuf démarre à zéro. L'app envoie un vrai petit lot de bienvenue depuis le trésor : 0,05 SOL, 5 USDC, 20 USDT, 5000 SKR.

Limite honnête : le SKR « misé » reste un compteur côté app (le staking va dans un trésor commun). Sans un vrai programme Solana dédié, la chaîne ne peut pas savoir « combien appartient à qui ». Le transfert lui-même est réel.

5. Fonctionnalités premium ajoutées

  1. Globe avec vraie physique (IDLE=0.12 rad/s, DAMP=1.85, MAX_OMEGA=9 rad/s).
  2. Globe agrandi pour remplir la largeur de l'écran.
  3. Icône de l'app à côté du mot « PUNCH » dans la barre du haut.
  4. Bouton « Quitter le réseau » avec vraie transaction blockchain obligatoire.
  5. Thème premium « Solana Seeker Mobile Gold ».
  6. Frais protocole réels sur entrée/sortie du réseau et retrait de staking.
  7. Onglet Réglages en plus des 5 onglets de l'app de base.

6. Habillage visuel — état actuel

  • Écran de connexion : minimal — éclair, « CLOCK IN », « Nexus paie la présence. », un bouton.
  • Après le pointage : ticket papier — « IN » énorme, heure, pays, règle 92/3/5, tampon on-chain.
  • Mode d'emploi interactif : 8 étapes, accessible depuis Réglages, PLI en teaser informatif seulement.

7. Pièges déjà rencontrés

  • Ne jamais généraliser un rayon de bordure — vérifier le vrai button.tsx de l'app de base.
  • Ne jamais confondre les anciens dossiers de référence avec le plus récent (le plus daté fait foi).
  • Les labels de boutons doivent décrire honnêtement l'action.
  • Toute fonctionnalité qui touche à l'argent = vraie transaction devnet dès le départ.
